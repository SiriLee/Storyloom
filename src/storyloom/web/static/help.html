1. Overview

Storyloom interacts with two kinds of API, but only one is required:

🧠 Text API (LLM) — required

Generates the narrative — story prose, dialogue, choices, and game state. The core engine of the game. Without a working text API, the game cannot run at all.

Interface: OpenAI-compatible /v1/chat/completions

Settings fields: API Base URL · API Key · Model

🎨 Image API — optional

Generates character portraits and scene backgrounds for visual novel / graph mode. Entirely optional. If left unconfigured or disabled, the game uses its built-in system media library — a curated collection of pre-made character art and backgrounds bundled with the program. The game is fully playable without ever setting up an image API.

You can enable image generation later at any time via the Image Generation toggle in Settings.

Interface: OpenAI-compatible /v1/images/generations

Settings fields: Image API URL · Image API Key · Image Model

💡 Key fallback: If Image API Key is left empty, Storyloom automatically falls back to your text API Key. If both APIs use the same provider and key, you only need to fill in the text API key and the image base URL + model.

2. Text API (LLM)

2.1 Quality requirement

Storyloom sends structured prompts to the LLM and expects strictly formatted output that the engine parses to drive game logic. Low-quality models are prone to malformed output — missing structure markers, garbled formatting, or incoherent branching logic. This causes errors that break the game flow.

⚠️ Quality floor: Avoid models smaller than ~20B parameters or older than 2024. They are likely to produce formatting errors. Stick to the Recommended tier or above.

3. Image API

🎭 You don't need an image API to play. Storyloom ships with a built-in system media library — a curated set of pre-made character portraits and scene backgrounds. When Image Generation is toggled off (or left unconfigured), the game draws from this library automatically. You only need to set up an image API if you want AI-generated custom artwork for your stories.

3.3 ⚠️ Seedream 5.0 — avoid for interactive use

Seedream 5.0 (both Pro and Lite) is NOT recommended for Storyloom.

Seedream 5.0 introduced a "deep thinking" / visual Chain-of-Thought step — the model runs an internal reasoning phase before generating the image. This reasoning phase is not controllable via API parameters and cannot be disabled. The result is dramatically longer total generation time than what marketing materials suggest:

ModelAdvertisedReal-world medianP95 tail
Seedream 5.0 Pro "high quality, reasoning-enhanced" 35–140s 140s+
Seedream 5.0 Lite "2–5 seconds" ~52 seconds ~69 seconds

Real-world data from API aggregator telemetry (Lumenfall, Aug 2026). Lite's advertised speed of 2–5s does not reflect actual API latency due to the mandatory reasoning step. Observed success rates are also notably low (~43%).

Storyloom's total image generation timeout is 300 seconds. A single Seedream 5.0 image can consume a large fraction of that budget just on reasoning — before any actual image generation. For an interactive game where images should appear within a reasonable time, this delay is unacceptable.

Use Seedream 4.5 or 4.0 instead. They produce comparable quality without the thinking overhead and with predictable, fast generation.

4.2 Quick setup example (APIYI)

Using APIYI as an example — other platforms follow the same pattern:

  1. Register at apiyi.com with your email.
  2. Top up (min $5, Alipay or WeChat).
  3. Go to the Token page and copy your API key (starts with sk-).
  4. In Storyloom's Settings, fill in:

💡 Same pattern for any platform: Replace the base URL and key with your chosen platform's credentials. The model names remain the same across all OpenAI-compatible aggregators — flux-2-pro is flux-2-pro everywhere.

5. Background Removal (Sprite Cutout)

5.1 What it does

Storyloom bundles a local AI model (U²-Net, ~4.4 MB) that automatically removes backgrounds from generated character portraits. This makes characters appear as sprites over scene backgrounds — the visual novel look. The model runs entirely on your device: no API calls, no network, no additional cost.

📌 Important: Background removal only applies to character portraits. Scene backgrounds always keep their original image — they are never cut out. No separate configuration needed beyond the dropdown below.

5.2 The three modes

ModeBehaviorWhen to choose
Auto Removes background only if the image lacks built-in transparency (alpha channel). If the model already outputs PNGs with transparent backgrounds, the step is skipped. Default. Recommended for most users. Transparent-output models skip the step automatically; opaque images get cut out.
Always Runs background removal on every portrait, even if it already has transparency. Use when your model produces inconsistent transparency, or the built-in transparency quality is poor. Adds ~1–2 seconds per portrait.
Never Skips background removal. Portraits shown as-is with their original background. Use for: (a) full-image portraits with background, (b) maximum speed, (c) models with consistently perfect built-in transparency.

5.3 Model compatibility

Among common image models, Seedream 5.0 Lite is the only one that outputs PNG with transparency. For all other models (FLUX, GPT Image, Gemini, Nano Banana, Seedream 4.x), the output is JPEG or opaque PNG — you'll typically want auto or always for the visual novel sprite look.

6. Troubleshooting

6.1 Text API errors

SymptomLikely causeFix
401 Unauthorized Invalid or missing API key. Verify your key in Settings. Check it starts with sk-. Ensure it hasn't expired.
403 Forbidden Insufficient balance, key lacks model access, or geo-restriction. Check your account balance. Verify the model is enabled for your key. Try a different provider.
404 Not Found Wrong base URL or model name. Double-check the exact model ID. Some platforms use prefixes (e.g. openai/gpt-5.2 on OpenRouter).
Stream stalls / no response Model overloaded, request timed out, or network issue. Try a different model. If on a slow connection, the timeout may need adjustment.
Output format errors Model quality too low — output is garbled or missing required structure. Switch to a higher-tier model (see §2.2). Avoid models below ~20B parameters.
Model emits thinking/reasoning text in output The model's thinking mode is on, and the API is returning reasoning content mixed with the response. Storyloom automatically sends thinking-disabled parameters for supported model families. If using an unsupported model, try switching to a known family or check the provider's console for a global thinking-mode toggle.

6.2 Image API errors

SymptomLikely causeFix
401 Unauthorized Invalid or missing image API key. Set Image API Key, or leave it empty to fall back to the text API key.
Image generation times out Model taking too long, especially Seedream 5.0 or during provider congestion. Switch to a faster model (FLUX, Seedream 4.x, Nano Banana). The timeout is generous (300s) — if you hit it, the model is too slow. See §3.3.
Image response missing data API response format doesn't match the expected structure. The provider may not be fully OpenAI-compatible. Try a different provider or model. Aggregation platforms (see §4) normalize formats.
Image is blank or corrupted Download failed or API returned malformed image data. Check the provider's status page. Try a different model. Missing images degrade gracefully — placeholders are shown instead.
Reference images not working Model doesn't support image references for character consistency. Nano Banana models lack reference image support. FLUX, Seedream, GPT Image, and Gemini all support it.
Unexpectedly high cost Using premium model at maximum resolution. Switch to a budget model. For portraits, 1024×1024 is sufficient — 4K is unnecessary for game sprites.

6.3 Background removal issues

SymptomLikely causeFix
Cutout looks rough / jagged edges U²-Net struggling with complex hair or translucent edges. This is a limitation of the local model. Try auto — if the model natively outputs transparency, the local step is skipped. Or use never for full-image portraits.
Model file not found at startup u2netp.onnx missing from installation. Reinstall Storyloom. The model is bundled as package data. From source builds, ensure the build step downloaded it.
Background not removed despite "Always" mode ONNX Runtime not installed or incompatible. Install onnxruntime. On ARM Linux, use onnxruntime (not the GPU variant).
