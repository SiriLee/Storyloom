# 流式解析

> 将首展示时间压缩到 TTFT。不改变桥接的必需性，但极大扩展其可行窗口。

---

## 为什么

不流式：用户等全部生成完毕 → 首展示时间 = 总生成时间 → 桥接窗口被压缩。

流式：内容边生成边展示 → 首展示时间 ≈ TTFT → 桥接窗口最大化。

流式还赋予另一关键能力：**解析器在内容生成过程中即可识别资源声明**，提前触发并行任务（素材生成、预取等），进一步缩短实际等待时间。

---

## 要求

流式解析对内容格式提出两条要求，与具体格式无关：

1. **增量可解析** — 不完整输入下能产出有效单元。不能等"全部完成"。
2. **位置可追踪** — 解析器需要知道"当前在内容流的什么位置"，用于时序计算和后续匹配。

任何能满足这两条的格式，均可作为流式输出格式。

---

## 与桥接的关系

桥接需要知道标记点在内容流中的位置。流式解析提供这一信息——标记被识别的同时，其位置即被确定，桥接的时序计算得以立即启动。

不流式：标记位置在全部内容解析后才得知 → 下一轮请求延迟发起 → 桥接窗口浪费。

流式：标记被识别即刻触发下一轮 → 桥接窗口最大化。
