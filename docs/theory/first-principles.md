# 第一性原理

> Storyloom 架构的理论根基。两个公理，一个目标，推导一切。

---

## 公理

**公理 1 — 生成有时延**

AI 内容生成耗时 > 0，且不可消除。当前技术条件下以秒到数十秒计。这是物理约束，不是工程问题。

**公理 2 — 交互含不确定**

交互式体验中，内容的生成存在时序依赖——后续内容由前置交互结果决定，该结果在交互发生前不可确定。若内容可完全预生成，则体验不是"交互式"的。这是定义性事实。

---

## 目标

**隐藏等待。** 用户感知延迟应被压缩到交互容忍范围内。暴露的等待使体验从"交互"退化为"等待生成"。

---

## 推导

### 桥接 — 结构性必需

由公理 1 + 公理 2：交互发生后必须等待生成。若不干预，感知延迟 = 生成时间，目标失败。

唯一出路：**生成与消费重叠。** 在当前内容尾部附加一段无需交互的缓冲内容，用消费这段时间覆盖下一次生成。这一机制——缓冲内容衔接下一轮生成——即桥接。

桥接从公理推导，**是结构性必需**。只要延迟存在、交互存在不确定性，就必须有某种形式的桥接。无替代方案。

### 流式解析 — 高效优化

若不流式：用户必须等待全部内容生成完毕才能开始消费。首展示时间 = 总生成时间。

流式解析将首展示时间压缩到 TTFT（首个可展示内容的到达时间），显著扩大桥接窗口。它是优化——极其有效的优化——但非结构性必需。

流式同时赋予另一能力：在内容生成过程中即可识别其中声明的资源需求，从而提前触发并行任务（素材生成）。

### 三层流与缓冲

```
生成（AI）→ 处理（程序）→ 消费（用户）
 慢/不可控     快/可控         人因节奏
```

层间速度差达数量级。若无缓冲，慢层阻塞快层。两个速度断层 → **两个解耦队列**：生成↔处理之间，处理↔消费之间。这是物理推论，非设计选择。

### 核心方程

```
实际等待 = TTFT + 素材剩余生成时间 − 消费覆盖时间
```

目标：使该值 ≤ 交互容忍阈值。桥接提供消费覆盖时间，流式压缩 TTFT，素材并行化缩短剩余生成时间。

---

## 不变量

流水线结构在以下变化中**保持成立**：

- **推理加速**：模型更快 → 所需缓冲更短 → 桥接点后移，但结构不消失
- **模态增加**：图像、音频、3D —— 各自有独立生成时间，服从同一重叠原则
- **交互形式演变**：文本选择、语音指令、动作输入 —— 公理 2 适用所有形式

结构终止的唯一条件：**T_gen < T_react**（生成总时间短于人类反应时间）。此时重叠从必需变为可选。
