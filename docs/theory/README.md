# Storyloom 设计理论

> 不可撼动的设计根基。若被推翻，项目本身需重新审视。

---

## 背景

AI 驱动的交互式内容面临一个根本矛盾：**生成需要时间，交互不应该等。**

现有两种范式各自回避了矛盾的一侧：

**批量预生成** — AI 在交互开始前产出全部内容。延迟为零，但用户的选择无法改变后续内容——因为内容已经生成完毕。自由度受限于预生成边界。适用于线性叙事（AI 生成的小说、视频），不适用于"玩家的选择影响故事走向"的交互体验。

**纯实时交互** — 每次用户输入，AI 即时响应生成。自由度极高——任何选择都可以被响应，内容方向完全开放。但每次响应前用户被动等待生成完成，延迟直接暴露。适用于对话式应用（ChatGPT），但等待破坏了"游戏"的沉浸感——玩家不是在体验，是在等生成。

Storyloom 探索第三种方向：**流水线生成。** 生成不发生在等待期间，而发生在用户消费当前内容的期间——通过桥接机制，在生成与消费之间创造时间重叠。目标是让交互式 AI 内容同时具备高自由度和低感知延迟。
