# Storyloom 设计理论

> **定位**：项目不可撼动的设计理念与理论基础。若被推翻，则项目本身需要重新审视。
>
> **与 `docs/spec/` 的关系**：spec 描述"怎么做"，随实现频繁更新。theory 描述"为什么"，仅在重大理念转变时修改。

---

## 背景

AI 在内容生成领域有两种成熟的使用范式：

**范式一：批量生成。** AI 一次性产出全部内容，生成结束后用户与产物交互。例如：用 AI 生成一部小说、一组游戏资产（图像、文本、音频）、一段视频。自由度低（受限于预生成内容），但延迟不存在（生成在交互前已完成），质量可通过人工审核保证。AI 是幕后的"内容工厂"。

**范式二：完全实时生成。** 每次用户输入，LLM 实时响应。例如：ChatGPT、AI 对话式游戏、实时图像生成工具。自由度极高，但延迟直接暴露——每次响应前用户只能被动等待。质量无中间检查，响应直达用户。

Storyloom 探索第三种方向：**以实时生成为基础，兼备流畅体验与自由度。** 生成发生在用户消费当前内容的期间，而非等待期间——通过结构化输出，在生成与展示之间创造重叠窗口。这一方向不是已有范式，其可行性仍在被验证。

| | 范式一：批量生成 | 范式二：完全实时 | Storyloom |
|---|---|---|---|
| **自由度** | 低（预设内容） | 极高（开放交互） | 中（输入受限） |
| **延迟** | 无（预先完成） | 暴露（每次等待） | 目标：隐藏 |
| **质量保证** | 人工审核 | 无 | 程序约束 |
| **状态** | 成熟范式 | 成熟范式 | 探索中 |

---

## 核心问题

选择这一方向意味着，两个现有范式各自回避的问题必须被同时正视。

### 问题 ①：内容质量保证

没有人工审核，但交互式内容对逻辑自洽的要求远高于自由交互。程序必须在无人介入的情况下把关——格式合规、逻辑自洽、方向不偏离。解决途径：提示词约束 + 格式化输出 + 本地数据（大纲、状态）锚定。

### 问题 ②：消解生成延迟

范式二暴露了延迟但未解决。延迟客观存在、无法消除，但"延迟"和"等待感"是两回事。唯一不需要更快 LLM 的方案：**让等待发生在用户正在体验的时候**。解决途径：桥接机制。

### 问题 ③：自由度与延迟的矛盾

隐藏延迟需要桥接——对用户的每种输入提前生成应对内容。这意味着自由度不能是无限的，必须在预期范围之内。自由度和延迟隐藏方向相反，目前尚无系统性解决方案。

## 更新规则

- **何时更新**：对核心问题的理解发生变化时；有新的理论发现可独立支撑一个设计维度时
- **何时不更新**：具体格式、参数、实现方式变化时——属于 spec 范畴
- **未来扩展**：新模态（如图像生成）可能引入新的理论问题，届时追加新文件
