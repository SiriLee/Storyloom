# §7.7 UI 图像模式 — 设计规格

> 基于 §7.1-7.6 已确定的事件格式与管线，设计视觉小说界面（立绘 + 背景 + 文本对话框）。
> 文本模式界面保持稳定不变。

## §1 架构分层

```
┌─────────────────────────────────────────────────────┐
│  index.html                                         │
│  ┌──────────────┐ ┌─────────────────────────────┐   │
│  │ main.css      │ │ graph.css (新增)             │   │
│  │ (文本模式)     │ │ .graph-view / .graph-bg     │   │
│  │ 不动          │ │ .graph-sprites / .graph-dialog│   │
│  └──────────────┘ └─────────────────────────────┘   │
│  ┌───────────────────────────────────────────────┐   │
│  │ game.js (控制器)                               │   │
│  │   if mode === "graph" → GraphRenderer.xxx()   │   │
│  └───────────────────────────────────────────────┘   │
│  ┌────────────────┐ ┌──────────────────────────┐     │
│  │ display.js      │ │ graph-renderer.js (新增)  │     │
│  │ (文本展示)       │ │ init / setBackground      │     │
│  │ 不动            │ │ setSprite / showDialog    │     │
│  └────────────────┘ │ clearSprite               │     │
│                      └──────────────────────────┘     │
└─────────────────────────────────────────────────────┘
```

**原则**：文本模式文件（main.css, display.js）零改动。图像模式新增独立文件，game.js 仅增加 mode 分支。

## §2 布局与视觉

### 2.1 整体布局

经典视觉小说布局（全屏背景 + 底部对话框）：

```
┌──────────────────────────────┐
│                              │
│     [背景图 全屏 cover]       │
│                              │
│        ┌──────┐              │
│        │ 立绘 │  (居中偏下)   │
│        └──────┘              │
│ ┌──────────────────────────┐ │
│ │  对话框 (底部半透明面板)    │ │
│ │  "叙事文本居中..."        │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

### 2.2 z-index 层级

| 层级 | 元素 | z-index | 说明 |
|------|------|---------|------|
| 0 | `.graph-bg` | 0 | 背景图，全屏 `object-fit: cover`，淡入过渡 |
| 1 | `.graph-sprites` | 1 | 立绘层，`position: absolute; bottom: 对话框高度` |
| 2 | `.graph-dialog` | 2 | 对话框面板，底部固定 |
| 3 | `.game-choices` | 50 | 选项面板（复用现有，对话框之上） |

### 2.3 对话框样式

- 背景：`rgba(22, 33, 62, 0.85)` （复用 `--bg-secondary` + 不透明度）
- 边框：`1px solid var(--border-color)` (`#2a2a4a`)
- 文字：`var(--text-primary)` (`#e0e0e0`)，居中对齐
- 字体：`var(--font-sans)`，字号跟随用户设置（`--font-lg` 默认）
- 圆角：`var(--radius-lg)` (`8px`)

### 2.4 立绘定位

- 居中偏下，`position: absolute; bottom: 对话框高度 + spacing`
- `left: 50%; transform: translateX(-50%)`
- `max-height: 55vh`，保持宽高比
- 多角色时并排（未来扩展）

## §3 组件接口

### 3.1 GraphRenderer（graph-renderer.js）

```javascript
const GraphRenderer = {
  init(container)         // 创建 .graph-view DOM，注入图层结构
  setBackground(url)      // 设置背景图 URL，带 fade-in transition
  setSprite(url)          // 设置立绘 URL
  clearSprite()           // 清除立绘（移除 img 元素）
  showDialog(text)        // 在对话框内追加 <p> 元素
  destroy()               // 清理 DOM，恢复纯文本布局
}
```

`init(container)` 创建的 DOM 结构：

```html
<div class="graph-view">
  <div class="graph-bg"><img></div>
  <div class="graph-sprites"></div>
  <div class="graph-dialog">
    <div class="graph-dialog-text"></div>
  </div>
</div>
```

### 3.2 Event 处理扩展

EventDispatcher 输出的 `segment` / `scene` / `state` 事件已包含可选 `assets` 字段：

```json
{
  "type": "segment",
  "text": "...",
  "char": "Aldric",
  "assets": {
    "char_portrait": "stub_default_portrait",
    "background_img": "stub_default_background"
  }
}
```

UI 层读取 `assets` 字段：
- `assets.char_portrait` → `GraphRenderer.setSprite("/media/char_portrait/{id}.png")`
- `assets.background_img` → `GraphRenderer.setBackground("/media/background_img/{id}.png")`

### 3.3 图片服务

- FastAPI 挂载：`app.mount("/media", StaticFiles(directory=media_dir))`
- 前端 URL：`/media/{asset_type}/{asset_id}.png`
- `asset_type` 使用 AssetType enum 的 value（`char_portrait`, `background_img`）

## §4 素材库初始化

### 4.1 目录结构

```
media/
  _asset_lib.json
  char_portrait/
    stub_default_portrait.png   ← temp/image_api_test/01_portrait_rgba.png
  background_img/
    stub_default_background.png ← temp/image_api_test/03_background.png
```

### 4.2 _asset_lib.json

```json
{
  "version": 1,
  "items": {
    "char_portrait": {
      "stub_default_portrait": {
        "name": "Default Portrait",
        "description": "Stub character portrait for 7.4-7.8 development",
        "use_count": 0,
        "serial": 1
      }
    },
    "background_img": {
      "stub_default_background": {
        "name": "Default Background",
        "description": "Stub background image for 7.4-7.8 development",
        "use_count": 0,
        "serial": 1
      }
    }
  }
}
```

### 4.3 初始化函数

`_init_stub_assets(media_dir: str)` — 在图像模式 GameLoop 初始化时调用：
1. 若 `media_dir` 不存在 → 创建目录结构
2. 若 `media_dir` 存在但无 `_asset_lib.json` → 创建默认库文件，复制 stub 图片
3. 若已存在 → 跳过（不覆盖用户数据）

## §5 共创过渡界面

复用 `cc-transition` 样式（co-create.js 已有），文案改为素材初始化相关。

流程：
```
用户点击 "Generate"
  → co-create.js: 显示 cc-transition ("Preparing your world" + 动画点)
  → POST /api/co-create/generate (阻塞等待)
  → 服务端完成素材预构建（当前 stub：几乎瞬时）
  → 隐藏 transition → 跳转游戏页
```

**实现**：在 `co-create.js` 的 generate 回调中，调用 API 前显示 transition，API 返回后隐藏。

### 6.1 模式传递

UI 需要知道当前模式才能决定是否初始化 GraphRenderer。通过 API 响应传递：

- `POST /api/co-create/generate` 响应增加 `game_mode` 字段
- `POST /api/game/{id}/start` 响应增加 `game_mode` 字段
- Router 将 `game_mode` 传递给 `GameView.render(container, gameId, title, gameMode)`

## §8 文本模式兼容性

- `main.css` 零改动 — 图像模式样式全在 `graph.css`
- `display.js` 零改动 — 图像渲染全在 `graph-renderer.js`
- `game.js` 仅在 `_buildDOM()` 中添加 `if (mode === "graph")` 分支
- `index.html` 中 `graph.css` 和 `graph-renderer.js` 可条件加载或始终加载（模块自检 mode）
- 文本模式 SSE 事件与 Phase 1 完全一致（EventDispatcher.dispatch 不变）
